# wiki-interest-radar

Скіл у форматі [Agent Skills](https://agentskills.io/specification) для B2C-фаундерів. Він відповідає на питання
«чи зростає інтерес до теми X у мовних розділах Вікіпедії, наскільки цьому можна довіряти і яку аудиторію
досліджувати далі». Дані беруться з Wikimedia Pageviews API та Wikidata. На виході агент отримує таблицю з
вердиктами й рівнем довіри, графік і односторінковий PDF-звіт.

Усю роботу з даними виконує власний код скіла (`scripts/`). Агент запускає 1–3 команди, копіює числа з
результату і не пише власного коду для запитів чи статистики. Скіл розрахований і перевірений на дешевій
моделі (Claude Haiku 4.5), див. [Оцінювання на Haiku 4.5](#оцінювання-на-haiku-45).

- [SKILL.md](SKILL.md) — інструкція для агента (87 рядків).
- [examples/](examples/) — три запити із завдання, прогнані через скіл: `summary.md`, `chart.png`, `report.pdf`.
- [ROADMAP.md](ROADMAP.md) — як розвивати скіл для складніших досліджень і більших обсягів даних.
- [AI_USAGE.md](AI_USAGE.md) — як використовувались AI-інструменти і як перевірявся їхній результат.

## Швидкий старт

Потрібні [uv](https://docs.astral.sh/uv/getting-started/installation/), Python 3.11+ (uv поставить сам, якщо
його немає) і доступ до `wikimedia.org`, `wikidata.org` та `*.wikipedia.org`.

**Встановлення як скіла.** Скопіюйте цю директорію як `wiki-interest-radar/` у каталог скілів агента:
`~/.claude/skills/` (Claude Code, для всіх проєктів), `<проєкт>/.claude/skills/` (для одного проєкту) або
каталог скілів іншого агента з підтримкою Agent Skills (наприклад, `.agents/skills/`). Далі просто
ставте питання, наприклад «Чи зростає інтерес до астрономії в україномовній Вікіпедії?». Агент сам
підхопить скіл за описом у `SKILL.md`.

```bash
git clone https://github.com/anonym-collaborator/wiki-interest-radar ~/.claude/skills/wiki-interest-radar
```

**Напряму з командного рядка:**

```bash
# 1) аналіз: тема → статті через Wikidata → перегляди → нормалізація → тренд, довіра, графік
uv run scripts/radar.py analyze --topic "intermittent fasting" --langs pl,cs
uv run scripts/radar.py analyze --basket "Learning English: English language; English grammar; IELTS; TOEFL" \
    --langs pl,cs,uk,tr,es,pt

# 2) односторінковий PDF із висновком
uv run scripts/radar.py report --run wir-runs/intermittent-fasting_pl-cs_24m --lang uk --notes "2–4 речення висновку"

# 3) перевірка, що всі числа у відповіді є в результатах
uv run scripts/radar.py check --run wir-runs/intermittent-fasting_pl-cs_24m --text "У чеській частка впала на 47%…"

# уточнення без повторного завантаження: інші мови, вікно, боти, ваги рейтингу
uv run scripts/radar.py analyze --from wir-runs/intermittent-fasting_pl-cs_24m --add-langs sk --agent all-agents
```

Перший запуск ставить залежності (~15 с). Версії всіх пакетів зафіксовані в `scripts/radar.py.lock`.
Кожна команда друкує готові наступні команди з абсолютними шляхами. Змінна `WIR_CONTACT` (email або URL)
додає ваш контакт в User-Agent, як просить [політика Wikimedia](https://foundation.wikimedia.org/wiki/Policy:Wikimedia_Foundation_User-Agent_Policy).
У код і репозиторій контакт не записується.

| Команда | Що робить |
|---|---|
| `analyze` | Тема(и) або кошик статей × мовні розділи → `summary.md`, `results.json`, `data.csv`, `chart.png`. `--from` повторно використовує попередній запуск і кеш. |
| `resolve` | Лише знайти статті теми в розділах через Wikidata (sitelinks, редиректи, неоднозначність). |
| `report` | Односторінковий PDF (+ PNG-прев'ю) українською або англійською з висновком агента. |
| `check` | Витягає числа з тексту відповіді й зіставляє з `results.json` з урахуванням одиниць (%, %/рік, на 1 млн, перегляди). Exit 5, якщо числа вигадані. |
| `verify` | Незалежна перевірка стійкості висновку: чи тримається зміна окремо на десктопі й мобільних, з ботами, без перших/останніх 3 місяців; один місяць перезавантажується з API в обхід кешу → robust / mixed / fragile. |
| `diff` | Що змінилося між двома запусками: припущення (мови, вікно, боти, ваги) і результати. |

Коди виходу: 0 ok · 2 немає що вимірювати · 3 погані аргументи (повідомлення каже, що виправити) · 4 тему не
знайдено у Wikidata · 5 `check` знайшов непідтверджені числа · 6 збій API (повторіть, кеш збережеться).

## Як це працює

1. **Тема → статті.** Тема шукається у Wikidata, а статті в кожному розділі беруться з sitelinks. Назви не
   вгадуються. Перегляди редиректів додаються до статті. Якщо статті немає, скіл пише **NO ARTICLE**: це
   прогалина контенту, а не нульовий інтерес. Він також показує статті, що лише згадують тему, але не
   підставляє їх замість відсутньої. Неоднозначні назви (Mercury) позначаються **AMBIGUOUS** з переліком
   значень і підказкою `--qid`.
2. **Дані.** Беруться щоденні перегляди `agent=user` (без ботів) за 24 повні місяці. Поточний неповний
   місяць відкидається. API не віддає дні з нулем переглядів, тому вони дописуються нулями. Усе кешується
   в SQLite, повторні й суміжні запити не ходять у мережу. Клієнт дотримується лімітів Wikimedia
   (User-Agent, ≤170 запитів/хв, Retry-After на 429).
3. **Нормалізація.** Головна метрика — перегляди на 1 млн переглядів усього мовного розділу. Розділи
   відрізняються за розміром більш ніж у 10 разів, і цілі розділи втрачають трафік. Наприклад, уся ukwiki
   за рік змінилась на −25%, і без нормалізації цей спад приписується темі.
4. **Ріст і тренд.** Рахуються три оцінки: 12 місяців проти попередніх 12, останні 6 місяців рік до року,
   і нахил Тейла–Сена з 95% ДІ та сезонним тестом Манна–Кендалла. Нахил рахується на ряді без сезонності
   й без днів-сплесків. Якщо оцінки розходяться, агент має дати діапазон, а не одне число.
5. **Довіра.** Скіл перевіряє малий обсяг, частку днів-сплесків (робастний z-score відносно ковзної медіани), частку ботів, сезонність,
   розбіжність оцінок, зміни трафіку всього розділу і відомі розриви в даних (`assets/known_breaks.json`,
   наприклад перекласифікацію ботів Wikimedia у 2025 році). З цього виходять вердикт (growing / flat /
   declining / mixed) і довіра (high / medium / low) з переліком причин. Агент цитує причини, а не
   вигадує їх.
6. **Рейтинг аудиторій.** Пресети balanced / momentum / size або ваги користувача
   (`--weights size=…,momentum=…,trust=…`). Скіл показує, чи стійкий рейтинг до зміни ваг.
7. **Відповідь.** Шаблон «Відповідь / Дані / Наскільки довіряти / Обмеження / Наступний крок». Перед
   надсиланням агент запускає `check`.

Деталі й джерела порогів описані в [references/methodology.md](references/methodology.md), значення кожного
поля — у [references/metrics.md](references/metrics.md).

## Оцінювання на Haiku 4.5

**Кейси** ([evals/evals.json](evals/evals.json)):

- три запити із завдання;
- `followup` — «а якщо з ботами і додати польську?»; очікується `--from`, а не новий аналіз;
- `ambiguous-en` — Mercury на de/fr, треба сказати, яке значення виміряно;
- `negative-sql` — питання не про скіл, скіл не має запускатися.

Асерти бувають механічні (скіл запускався, PDF на одну сторінку, прапорці `--from`/`all-agents`, усі
числа відповіді є в `results.json`) і регулярні вирази на зміст.

**Як запускалось.** `evals/run_evals.py` проганяє кейси через `claude -p` зі скілом у `.claude/skills/`.
У цьому середовищі CLI не був залогінений («Not logged in»), тому ітерації прогнано субагентами Claude Code
з `model: haiku`. Кожен субагент працював у своїй чистій директорії і отримував репліку користувача;
у гілці `with_skill` він також отримував шлях до скіла («прочитай SKILL.md»). Фінальні відповіді збережено
дослівно, метрики (виклики інструментів, токени, секунди) взято зі звітів субагентів. Оцінює
`evals/grade_dir.py`, результати лежать у `evals/results/<ітерація>/RESULTS.md` і `grading.json` по кожному
прогону.

**Ітерація 2** (фінальна версія скіла):

| Кейс | Зі скілом | Без скіла | Виклики, зі / без | Токени, зі / без | Секунди, зі / без |
|---|---|---|---|---|---|
| if-pl-cs | 5/5 | 2/3 | 3 / 32 | 43 779 / 66 736 | 51 / 395 |
| astro-uk | 5/5 | 3/3 | 4 / 16 | 43 343 / 57 970 | 48 / 231 |
| english-report | 5/5 | 1/3 | 6 / 17 | 52 528 / 63 649 | 94 / 296 |
| followup | 5/5 | — | 4 + 2 | 48 245 | 43 + 51 |
| ambiguous-en | 2/2 | — | 3 | 42 636 | 31 |
| negative-sql | 1/1 | — | 2 | 41 646 | 26 |
| **Разом** | **23/23** | **6/9** | | | |

Токени включають ~40 тис. базового контексту агента. Для базової лінії скіло-специфічні асерти (запуск
скіла, числа з `results.json`, прапорці CLI) не рахуються, тому в неї менший знаменник.

**Ітерація 1:** зі скілом 21/22. Кейс `ambiguous-en` провалився: Haiku виміряв планету, але не сказав, що
Mercury неоднозначний. Після цього з'явилась позначка AMBIGUOUS у summary і правило в `SKILL.md`, і в
ітерації 2 кейс пройшов. Базова лінія мала 1/9, але дві з трьох її відповідей обірвав ліміт сесії, тому
для порівняння коректна лише ітерація 2.

**Що не видно з балів.** Регулярні асерти перевіряють наявність слів, а не правильність. Базова лінія
набирає бали там, де помиляється по суті:

- **if-pl-cs:** без скіла Haiku написав, що інтерес у чеській Вікіпедії *зростає* на +24,5%. Він порівняв
  перший місяць із останнім, причому останній був поточним неповним, на сирих числах і разом зі сплеском.
  Для польської він підставив інші статті про харчування (+564%). Асерт «states confidence» зарахувався
  через слово «Середньомісячні». Скіл: частка знижується на 47% за 12 місяців, тренд −40%/рік
  [−48; −29], довіра середня через малий обсяг і дні-сплески; у польській статті немає.
- **astro-uk:** без скіла відповідь була «−17% в середньому», сирі зміни по кількох статтях, без
  нормалізації, «надійність 10–20%» (число вигадане). Порада: Вікіпедії не довіряти взагалі. Скіл:
  частка на 1 млн −46%, тренд −46%/рік [−51; −36], довіра висока; спад усієї ukwiki (−25%) уже прибрано;
  спад сповільнюється (−10% за останні 6 місяців рік до року).
- **english-report:** без скіла Haiku рахував *кількість редагувань* статей, а не перегляди. PDF вийшов
  на 2 сторінки, мовні розділи названо країнами. Скіл порівнює частку на 1 млн: найбільша в uk (127),
  стабільний лише tr (+1%), рейтинг залежить від ваг.
- Зі скілом Haiku робить 2–6 викликів замість 16–32 і витрачає в 3–8 разів менше часу.

**Чесні застереження.**

- По одному прогону на кейс. Кейси й скіл написав один автор.
- В ітерації 2 `with_skill`-агенти отримували шлях до скіла, тож спрацювання скіла за описом перевірено
  лише негативним кейсом.
- Після ітерації 2 змінено дві речі (обидві розкриті в [AI_USAGE.md](AI_USAGE.md)):
  - розбір чисел у `check`: «на 1 мільйон», «12-місячне» і попередження про текст іншим письмом;
  - регулярний вираз «explains a trust factor», якому бракувало «у цілому».

  Без цих змін ітерація 2 мала 21/23, і обидва провали були хибними спрацюваннями оцінювача, а не
  помилками відповіді.

## Обмеження та відомі слабкі місця

- **Перегляди — це увага, а не готовність платити.** Скіл дає напрям для перевірки, і кожна відповідь
  закінчується кроком валідації.
- **Мовний розділ ≠ країна.** Португальську читають у Бразилії й Португалії, іспанську — у двадцяти
  країнах.
- **Стаття чи кошик ≠ уся тема.** Кошик складає агент (2–5 статей). Автоматичне розширення кошика
  є в ROADMAP.
- **Фільтр ботів неідеальний.** Wikimedia перекласифікувала частину трафіку 2025 року, і це позначено
  у звітах. Скіл показує частку ботів і вміє рахувати з ними (`--agent all-agents`).
- **Малі обсяги** (одиниці переглядів на день) дають низьку або середню довіру. Це правильна поведінка,
  але для рідкісних тем відповідь часто звучить як «даних замало».
- **Слабкі місця Haiku, помічені в evals:**
  - у звіті про англійську Haiku називав розділи країнами («Туреччина», «Польща»), хоча є правило;
  - траплялися спотворені слова;
  - у проміжній відповіді з'явився китайський фрагмент.

  `check` тепер попереджає про текст іншим письмом, але спотворену кирилицю не ловить.
- **Швидкість першого запуску.** Кожна пара «стаття × розділ» — окремий запит. Для великих запитів
  (≫60 пар) варто перейти на дампи, див. ROADMAP.

## Структура

```
SKILL.md                 інструкція для агента
scripts/radar.py         точка входу (PEP 723-залежності), radar.py.lock фіксує версії
scripts/wir/             код: net, fetch, cache, resolve, langs, series, stats, analysis, ranking,
                         summary, charts, report, check, verify, diffrun, i18n, cli
references/              metrics.md, methodology.md, troubleshooting.md (читаються за потреби)
assets/                  wikipedias.json (розділи), known_breaks.json (відомі розриви в даних)
examples/                три запити із завдання
tests/                   25 тестів pytest
evals/                   evals.json, run_evals.py (claude -p), grade_dir.py, results/
```

Розробка:

- тести: `uv run tests/run_tests.py`;
- валідація: `uvx --from skills-ref agentskills validate <абсолютний шлях до скіла>` (з відносним шляхом `.`
  валідатор 0.1.1 помилково скаржиться на порожню назву директорії);
- evals: `uv run evals/run_evals.py --cases all` (потрібен залогінений `claude`) або
  `uv run evals/grade_dir.py --root <директорія прогонів> --out evals/results/<ітерація>`.
