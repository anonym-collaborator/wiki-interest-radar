# Як використовувались AI-інструменти

Скіл розроблено разом з агентом Claude Code, у двох сесіях: у застосунку Claude і в VS Code. Для
перевірки на дешевій моделі використано субагентів Claude Haiku 4.5. Нижче описано, що робив кожен
інструмент і як перевірявся його результат. Головний принцип: жоден результат AI не вважався
правильним, поки його не підтвердили тест, прямий запит до даних, незалежна перевірка (`check`,
валідатор, `pypdf`) або ручне прочитання.

## Хто що робив

| Задача | Інструмент | Результат | Як перевірено |
|---|---|---|---|
| Розбір завдання, дослідження Wikimedia API (ліміти, User-Agent, особливості даних), подібні рішення | Claude Code + вебпошук і читання документації | план, список підводних каменів даних, вибір стеку (Python + uv) | звірено з документацією Wikimedia і реальними відповідями API під час розробки; рішення щодо обсягу, стеку й моделі для evals ухвалила людина |
| Код скіла (`scripts/wir/`) | Claude Code | ~2600 рядків Python | 25 тестів pytest, прогони на реальних даних, `verify` (звірка місяця з API в обхід кешу), перегляд графіків і PDF |
| Інструкція для агента (`SKILL.md`, `references/`) | Claude Code | 87 рядків `SKILL.md` + 3 довідки | валідатор `agentskills validate`; поведінка Haiku в evals |
| Тестування на дешевій моделі | субагенти Claude Haiku 4.5 (зі скілом і без) | 2 ітерації × 6 кейсів | `evals/grade_dir.py` + ручне прочитання кожної відповіді |
| Приклади, README, ROADMAP | Claude Code | `examples/`, документація | числа у висновках PDF пройшли `check`; описи команд звірено з кодом |

## Що AI зробив неправильно і як це знайдено

**Дані й API**

- **API не віддає дні з нулем переглядів.** Без дописування нулів середні й тренди малих тем
  завищуються. Тепер пропуски дописуються нулями (тест `test_zero_days_are_filled_and_cached`).
- **Місячний endpoint повертає поточний неповний місяць.** Він штучно «обвалює» кінець ряду. Такий
  місяць відкидається, а місяць вважається повним через 2 дні після кінця (тести
  `test_monthly_drops_partial_month_after_end`, `test_last_complete_month_respects_loading_lag`).
- **Стандартний User-Agent упирається в ліміт 10 запитів/хв і отримує 429.** Тепер використовується
  власний User-Agent з URL проєкту та `WIR_CONTACT`, запити йдуть послідовно з паузою, а на 429 скіл
  чекає `Retry-After`.
- **Перегляди редиректів рахуються окремо від статті.** Скіл їх сумує, і summary показує
  «+N redirects».

**Середовище розробки (Windows)**

- **Патчі через bash-heredoc ламали кирилицю у файлах.** Правки робились лише інструментами
  редагування файлів, вивід скіла завжди в UTF-8.
- **В оболонці агента не було `LOCALAPPDATA`.** Через це псевдонім `python.exe` (Windows Python install
  manager) під час пошуку інтерпретатора ставив Python 3.14 (~170 МБ) у поточну директорію, зокрема в
  директорію скіла. Це знайшла перевірка перед комітом (пошук сторонніх файлів і персональних даних).
  Папку перенесено з репозиторію, рядок додано в `references/troubleshooting.md`, шлях — у `.gitignore`.
- **`agentskills validate .` скаржиться на порожню назву директорії.** З абсолютним шляхом валідатор
  проходить. Це описано в README.

**Evals і оцінювач**

- **`claude -p` у цьому середовищі не був залогінений,** і смоук-прогін повернув «Not logged in». Ітерації
  прогнано субагентами Haiku 4.5 з тими самими промптами. Відповіді збережено дослівно, метрики взято
  зі звітів субагентів. Сам `run_evals.py` лишився для середовищ із залогіненим CLI.
- **Помилка в оцінювачі:** `"without_skill".startswith("with")` дорівнює `True`, тож базова лінія
  оцінювалась асертом «скіл використано». Підозріло низький бал (1/15) змусив перечитати код. Тепер
  скіло-специфічні асерти для базової лінії не рахуються (`NOT_SCORED_WITHOUT_SKILL`).
- **`check` хибно спрацьовував на відповідях Haiku.** Він читав «9,89 переглядів на 1 мільйон» як
  кількість переглядів, а «12-місячне» як число 12. Регулярні вирази виправлено, додано регресійний тест
  `test_extract_numbers_formats_seen_in_haiku_answers`. Це виправлення самого скіла, бо агент теж
  запускає `check`.
- **Регулярний вираз асерта «explains a trust factor» не знаходив формулювання** «у цілому … втратила
  25%», хоча відповідь пояснювала нормалізацію. Вираз розширено. Це зміна оцінювача, а не скіла, тому
  вона розкрита в README разом із балом до виправлення (21/23).
- **Регулярні асерти щедрі до базової лінії:** «states confidence» зарахувався через слово
  «Середньомісячні». Тому README порівнює відповіді по суті, а не лише бали.

**Поведінка Haiku 4.5, знайдена прочитанням відповідей**

- **Ітерація 1, `ambiguous-en`:** Haiku виміряв Меркурій-планету і не сказав, що назва неоднозначна.
  Додано позначку AMBIGUOUS у summary і правило «перше речення називає виміряне значення». В ітерації 2
  кейс пройшов.
- **Без скіла Haiku вигадує або підмінює:**
  - одного разу заявив, що API закритий, і відповів без даних;
  - в інших спробах рахував кількість редагувань замість переглядів;
  - порівнював перший місяць з неповним останнім («+24,5%» замість спаду);
  - вигадав «надійність 10–20%».

  Саме від цього захищають правила `SKILL.md`: числа лише з виводу скіла, NO ARTICLE — прогалина, а не
  нуль, кожен ріст подається з вердиктом і довірою.
- **Зі скілом Haiku іноді вставляє фрагмент іншим письмом** (китайський посеред українського речення).
  `check` тепер про це попереджає (`test_check_warns_about_text_in_another_script`).
- **Haiku називає мовні розділи країнами** («Туреччина», «Польща»), хоча правило є. Це задокументовано
  як відоме слабке місце, автоматична перевірка запланована в ROADMAP.

**Документація**

- **Опис команди `verify` у чернетці README був неточним:** його написано з пам'яті, а не з коду.
  Звірено з `scripts/wir/verify.py` і виправлено. Так само звірено параметри `run_evals.py` та опис
  детектора сплесків.

## Що перевіряється автоматично і може бути повторено

```bash
uv run tests/run_tests.py                                      # 25 тестів
uvx --from skills-ref agentskills validate <абсолютний шлях>   # формат Agent Skills
uv run scripts/radar.py check --run examples/astronomy_uk --text "…"   # числа у тексті ↔ results.json
uv run evals/grade_dir.py --root <прогони> --out evals/results/<ітерація> --meta <meta.json>
```

Відповіді Haiku і `grading.json` кожного прогону лежать в `evals/results/haiku-it1/` і
`evals/results/haiku-it2/`, тож оцінки можна перевірити вручну.
